# DECISIONS.md — orchestration decisions where the spec is silent

| Date | Decision | Reason |
|------|----------|--------|
| 2026-09-05 | Renamed default branch `master` → `main`; baseline scaffold (design system, docs, compose) committed as one commit before Phase 0 branch. | TOOLING.md workflow assumes `main`; repo had a single `Init` commit on `master` plus uncommitted work. |
| 2026-09-05 | SMS provider selection by env: `BEEM_API_KEY` empty → `LogProvider` (logs recipient + body incl. OTP to API log); non-empty → Beem. | Beem creds absent; PLAN.md Phase 1 says dev mode logs OTP. |
| 2026-09-05 | Backend runs on host :8081 in dev (`make api`), behind proxy `/api/*`. Migrations run via `go run ./cmd/api migrate up` (golang-migrate as library) so no extra CLI install. | Orchestrator prompt §2; fewer host dependencies. |
| 2026-09-05 | MinIO bucket for unit QR PNGs is `qrcodes`, not `qr` (SPEC §7). | MinIO/S3 rejects bucket names under 3 chars. Compose init uses `--ignore-existing`. |
| 2026-09-05 | Compose Postgres published on host port **5433** (`POSTGRES_HOST_PORT`), `DATABASE_URL` uses :5433. | Host-native Postgres already owns :5432; not ours to stop. |
| 2026-09-05 | One session cookie per audience (`tms_r` renter, `tms_o` org user, `tms_a` admin). | Lets one browser hold renter + landlord sessions during testing; routes are already audience-partitioned. |
| 2026-09-05 | Email delivery behind `EmailProvider` interface; dev implementation logs verification/invite links to the API log. Login is allowed before email verification (`email_verified` flag surfaced in UI banner). | No mail provider in scope; keeps dev loop unblocked. |
| 2026-09-05 | `users.full_name` column added (spec lists it only on renter_profiles). | Org users/admins need a display name for audit + signatures. |
| 2026-09-05 | `make build` for Next apps uses `NEXT_DIST_DIR=.next-build` (`distDir` in next.config) so builds don't clobber the running dev servers' `.next`. | Preview must keep running during orchestration. |
| 2026-09-05 | Client IP: trust `X-Forwarded-For`/`X-Real-IP` only when the direct peer is loopback or in `TRUSTED_PROXY_CIDRS` (default `127.0.0.0/8,::1/128`). | Rate limits + audit IPs must not be spoofable; the Go proxy is the only trusted hop. |
| 2026-09-05 | In `ENV=prod` the API refuses to start with the dev `LogProvider` for SMS/email (missing Beem creds). | OTP codes must never reach production logs. |
| 2026-09-05 | Presigned MinIO URLs are signed against `MINIO_PUBLIC_URL` (default = `APP_BASE_URL`), and the Go proxy forwards `/branding/*`, `/qrcodes/*`, `/kyc/*`, `/signatures/*` to MinIO :9000 without rewriting Host or path. | Presigned `localhost:9000` links are unreachable from phones via ngrok; bucket-name prefixes never collide with app/API paths. |
| 2026-09-05 | `renter_profiles.kyc_status` keeps its Phase 1 `incomplete` value in the column; the API translates it to `none` (API.md) at the edge. | Avoids migrating existing rows for a purely cosmetic wire value. |
| 2026-09-05 | Errors API.md names by code (`unit_occupied`, `kyc_required`, `period_not_offered`, `duplicate_request`, `not_pending`, `unit_unavailable`) carry the code in the RFC-7807 `type` field. | The document already has a `type`; a parallel `code` field would duplicate it. |
| 2026-09-05 | `POST /units/{unit_code}/link` answers 404 on an `unlisted` unit (as the public endpoint does) and 409 `unit_unavailable` on a `maintenance` one. Spec names only the occupied case. | An unlisted sticker must read as an unknown code; maintenance is a real, temporary refusal worth distinguishing. |
| 2026-09-05 | `start_date` accepts `today−7 … today+365`; `PUT /me/profile` requires next of kin. | Spec fixes only the −7 backstop; the ceiling stops a request reserving a unit indefinitely, and next of kin is required to reach `kyc_status: submitted`, which gates linking. |
| 2026-09-05 | Approving a link request leaves the unit `vacant`; `onLinkApproved(ctx, q, req)` in `link_handlers.go` is the (no-op) seam where Phase 4 creates the contract. | A unit becomes occupied when a contract activates, so an approved-then-abandoned request cannot strand it. |
| 2026-09-05 | `notification_log` gains `to_phone`, `body`, `error`, `attempts`; the Phase 3 worker makes one attempt with no backoff. | The worker sends from a single row read; the 3-attempt retry pool is Phase 6 scope (SPEC §6). |
| 2026-09-05 | `unit_link_requests.reason` (000002) replaced by `rejection_reason` in 000004. | Two columns for the same fact leave two places to look. |
| 2026-09-05 | Auto-approved link requests have `decided_by_user_id` NULL (system decision). `end_date` is exclusive: `end_date = start_date + term_days` (SPEC §4) — the day after the last schedule row's inclusive `period_end`. | Spec silent on the auto-approve actor; the end-date convention is SPEC §4's, and the enduser preview was realigned to it. |
| 2026-09-05 | Link approval creates the contract in the same transaction (manual + auto-approve) from the org default template; approving an already-approved request with no contract backfills one. Approval fails whole if the contract cannot be written (unpriced unit, no template). | FLOWS 3.3; a renter must never be told "approved" with nothing to sign. |
| 2026-09-05 | Landlord countersign on the FLOWS 3.6 path records `contract_signatures.method = landlord_recorded` with a required reason; normal activation records `otp_accept` via session. Contract reads (`{id}`, `/document`, `/verify`, `/schedules`) accept renter or org audience; writes stay one-sided. | Spec silent on method value for the no-phone case; audit needs the distinction. |
| 2026-09-05 | Termination waives schedules whose `period_start` is after `effective_date`; the period in progress stands. `due_day` falls back to `orgs.settings.due_day`. | Simplest rule consistent with FLOWS 6.5. |
| 2026-09-05 | An overpayment lands on the schedules *after* the target, in due order, skipping settled and waived rows; one on the last unpaid schedule answers 409 `exceeds_contract_balance` (not `overpay_confirm_required` — there is nothing to prompt about). | API.md fixes the rollover but not the edge; a confirm prompt with no destination is not a prompt. |
| 2026-09-05 | Recording a payment sets only `paid`/`partial` (API.md); the overdue re-flag is left to the sweep, which every schedule read runs org-scoped first, so no client can observe the gap. | API.md's record and reverse rules disagree on `overdue`; this keeps both literal without a stale read. |
| 2026-09-05 | `payments.status` keeps its 000002 `confirmed` value in the CHECK constraint even though Phase 5 only ever writes `recorded`/`reversed`. | `confirmed` is the reserved gateway seam (SPEC §5.7); narrowing it now would have to be widened again. |
| 2026-09-05 | The on-demand overdue sweep run by `GET /schedules` and `GET /me/schedules` is not audited; only `POST /admin/jobs/overdue` writes `payment.overdue_run`. | A read's own housekeeping would otherwise write an audit row per page view and bury the trail. |
| 2026-09-05 | `GET /me/schedules` shows the bank account of the org behind `next_due` only (a renter may rent from several orgs); with nothing outstanding, `bank_account` is `null`. | API.md gives one `bank_account` field for a possibly multi-org list; the account that matters is the one for the next payment. |
| 2026-09-05 | `POST /payments` on a fully settled contract, and one naming a schedule of another contract, answer 409 `exceeds_contract_balance` and 404 respectively. | Spec silent; both follow the existing "id not in your scope is a 404" and "money the contract cannot take is refused" rules. |
| 2026-09-05 | `GET /schedules` pages by `(due_date, id)` ascending rather than the `(created_at, id)` descending cursor the other listings use. | The board is read forward — the next thing owed is the first thing shown. Same cursor encoding, so clients treat it identically. |
| 2026-09-05 | `orgs.settings.notifications` holds sender name, send hour, per-kind toggles and template overrides; `language` in the notification-settings endpoint reads and writes the existing `orgs.settings.sms_language` rather than storing a second copy. | Two places to set one language is two places for it to be wrong; API.md names the field `language`, and PATCH `/org` already names it `sms_language`. |
| 2026-09-05 | The org template whitelist is exactly API.md's eight variables. The platform defaults additionally use `{{reason}}`, `{{start_date}}` and `{{next_amount}}`; an org override of those kinds simply does without them. An override of `thank_you` replaces both the "next payment" and the "all paid" wordings. | The whitelist is a locked contract; widening it silently would be a deviation, and the extra three belong to one kind each. |
| 2026-09-05 | `notification_log.status` gains `sending`, the state between the worker's atomic claim and the provider's answer. The startup sweep returns rows left `sending` for over five minutes to `queued`. | The claim (`… WHERE status='queued' RETURNING`) needs a status to move to; without the sweep a crashed worker would strand the message. |
| 2026-09-05 | With `MaxAttempts` at API.md's three, the 1s/5s/25s backoff schedule uses 1s and 5s (the pauses between attempts); the 25s rung is kept in the table as the next step. Delays are injectable so tests do not spend six seconds per failure. | Three attempts have two gaps between them; the schedule is written down whole rather than truncated. |
| 2026-09-05 | `POST /notifications/custom` with `selected` counts an unrelated renter id as `skipped`, never a 404. A renter with no phone on file is also `skipped`. | A broadcast must not become a way to probe another org's directory, and one missing number must not fail a batch of forty. |
| 2026-09-05 | The scheduler walks orgs one at a time with org-scoped queries rather than one cross-org sweep, so the isolation guard applies to it unchanged. `RunOnce` takes no Redis: the caller enqueues the ids it returns. | Keeps the sweep testable against a bare database, and keeps Redis carrying the work item rather than the truth (SPEC §2.2). |
| 2026-09-05 | The sender ID is resolved inside the worker's claim (`orgs.settings->notifications->sender_name`) rather than stored on the notification row. Auth OTPs send with the platform default (no org is known yet); the contract-signing OTP uses the landlord's. | One round trip on the send path, and a sender-name change applies to messages already queued. |
| 2026-09-05 | `GET /admin/jobs` reports each job's last run from the newest `audit_log` row for its action (`contract.lifecycle_run`, `payment.overdue_run`, `notification.scheduler_run`) rather than from a new `job_runs` table. Migration 000009 adds only `orgs.suspended_at` / `orgs.suspended_reason` and an `(action, at DESC)` index. | The jobs already audit themselves; a second store could only disagree with the first. |
| 2026-09-05 | Suspension is enforced in `RequireOrg` (and the org half of `RequireContractParty`) as 403 `org_suspended`, decided by a Redis flag `org:suspended:{id}` written on suspend/activate with a cached `SELECT status FROM orgs` fallback. Renters and platform admins are unaffected, and login itself still succeeds. | Redis is ephemeral (SPEC §2.2), so a missing flag must cost a query, never open a suspended org. A renter is not suspended because their landlord is, and an operator needs "wrong password" to stay distinguishable from "org closed". |
| 2026-09-05 | A suspended org's queued SMS is left `queued` — `ClaimNotification` gains `AND o.status = 'active'`, so the claim finds nothing and the worker returns as it does for an already-taken row. Nothing is marked `failed`. | Reactivation should release the backlog, not leave a trail of errors the landlord has to retry one by one. |
| 2026-09-05 | Report periods and collections buckets are read on the Dar es Salaam wall clock (the zone SPEC §6 already uses for send hours); occupancy is `occupied / (occupied + vacant)`, excluding `unlisted` and `maintenance`; `days_vacant` counts from the last ended/terminated contract's `end_date`, else the unit's creation. | API.md fixes the shapes, not the boundaries. A month must be the month it is where the landlord stands, and a room taken off the market is not a vacancy they are failing to fill. |
| 2026-09-05 | `POST /admin/orgs/{id}/suspend` requires a non-empty `reason` (stored on the org and in the audit `after`); activate clears it. `dashboard_prefs` refuses unknown keys as well as unknown card ids. | Suspending a tenant without saying why is the one admin action nobody can reconstruct afterwards; silently dropping a setting a landlord thought they saved is worse than a 400. |
| 2026-09-05 | Exactly **one** recommended payment period per org, enforced by a partial unique index (`payment_periods (org_id) WHERE is_recommended AND deleted_at IS NULL`); bootstrap and seed badge Monthly, `POST /org/payment-periods/{id}/recommend` moves it, and the other three seeded presets stay restorable but unbadged. | A badge on all four presets told the renter nothing, so "recommended first" was not an ordering at all (client request #8, confirmed 5 Sep). |
| 2026-09-05 | `{{rent}}` in a contract template is the amount **per payment period** (`round(rent_amount × payment_period_days / rent_period_days)`, the schedule's own rounding); the unit's price basis moves to a new `{{rent_basis}}` variable, and `GET /contracts/{id}` carries `rent_per_period`. Existing signed contracts are untouched (snapshot rule) and `snapshot_hash` is unaffected — the hash covers already-rendered terms. | The test contract read "TZS 100,000 per Quarterly (90 days)" for a 100,000-per-30-days room: the signed document stated the wrong figure. Only new contracts can change; a re-issue is the fix for an existing one. |
| 2026-09-05 | Language is stored per user (`users.locale`, `sw|en`, default `sw`), chosen at registration/signup; `orgs.settings.sms_language` survives only as the fallback for renters with no preference, and public pre-login pages default to the org language with a visible SW/EN toggle whose choice is carried into registration. | One renter's language is a fact about the renter, not about their landlord; the toggle gives a first-time scanner a way in before any account exists. |
| 2026-09-05 | SMS credits are prepaid per org with **no expiry and no monthly reset**, debited at send time at **1 credit per 160-character GSM segment** (70 for UCS-2), with `otp`/security kinds exempt; an empty balance parks the row as `held_no_credit` (never `failed`) and a top-up releases held rows in queue order. | PLAN2 open question 1's defaults, confirmed with the client. Charging per segment matches what Beem bills; `failed` would invite retries that cannot succeed. |
| 2026-09-05 | Platform message templates move from Go constants into `platform_templates` (seeded by migration, so the table is authoritative from day one; the constants remain the last-resort fallback), with a per-kind `locked` flag — `otp` locked out of the box — and an org override of a locked kind refused with 409 `template_locked`. | The admin needs to edit wording without a deploy (#12), and the OTP message is security copy no landlord should be able to rewrite. |
| 2026-09-05 | One org theme applies to **both** the landlord and the renter apps; the admin app is never themed. | PLAN2 open question 4's default: a renter and their landlord are looking at the same business, and platform staff must always see the platform's own chrome. |
| 2026-09-05 | Expense receipts live in a new MinIO bucket `receipts`, key `{org_id}/{expense_id}.{ext}`, ≤ 5 MiB, `image/jpeg`/`image/png`/`application/pdf`. | PLAN2 open question 5's default (PDF allowed); a separate bucket keeps the presigned-path prefix rule of the other buckets and lets the receipt policy differ from KYC's. |
